
# Lambda
이 코드를 실행해줘라고 요청할때만 잠깐 켜졌다 사라지는 실행 서비스

1. 15분 실행 제한이 있으니 처리에 그 이상의 시간이 걸리면 Lambda를 제외하고
   ECS/Fargate 나 AWS Batch를 고르자
   
2. vpc에 붙은 Lambda는 인터넷에 나가려면 NAT 게이트웨이가 필요하고 S3,DynamoDB에는
   vpc 엔드포인트로 무료로 나가자
   
# ECS
여러 개의 도커 컨테이너를 언제 어디서 실행하지 지시하고 관리하는 관제 서비스

1. 시작유형이 EC2면 직접 관리하고, Fargate면 서버관리가 사라진다.

2. 태스크 vs 실행
   태스크 역할은 컨테이너 안의 애플리케이션이 S3 등 AWS API를 호출할때 쓰는 권한이다.
   실행 역할은 ECR에서 이미지를 당기고 CloudWatch에 로그를 쓰는 권한이다.

3. ALB 와 동적 포트 매핑
   하나의 EC2에 여러개의 같은 컨테이너를 띄울려면 ALB의 동적 포트 매핑을 사용한다.
   동적 포트 매핑이란 한개의 EC2 서버에 3개의 같은 컨테이너가 들어온다치면 
   이름은 같지만 포트를 자동으로 다르게 배정하고 ALB가 그 포트들을 알아서 찾아간다.

# Fargate
컨테이너를 서버 관리 없이 실행해 주는 서비스, ECS나 EKS에서 컨테이너를 돌릴때
EC2 서버를 직접 준비하고 관리해주는 대신, 컨테이너가 필요한 CPU와 메모리만 지정해주면
AWS가 알아서 실행해준다.

1. Lambda 와의 선택 기준
   둘 다 서버리스지만 Lambda는 15분/이벤트 기반, Fargate는 장시간 실행/상주 서비스이다.
   "컨테이너 이미지를 그대로 써야한다", "15분을 넘는다" 면 Fargate를 사용한다.
   
2. 비용관련
   Fargate는 비용이 높고 상시 돌아가는 워크로드에서는 EC2 시작유형보다 비싸다.
   "가장 저렴" 을 물으면 EC2 시작유형이 답이 될 수 있다.
