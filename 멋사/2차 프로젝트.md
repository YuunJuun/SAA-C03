  지금부터 Qket 서비스의 메인 페이지를 대상으로 접속 부하 테스트를 진행하겠습니다.
테스트 도구는 k6를 사용하고, 운영 중인 EKS 환경의 상태는 Prometheus와 Grafana를 통해 실시간으로 확인하겠습니다.

대시보드에서는 초당 API 요청 수, 5XX 서버 오류, 프론트엔드와 백엔드의 CPU 및 메모리 사용량, 그리고 실행 중인 Pod 수를 확인할 수 있습니다.
현재는 테스트 시작 전이기 때문에 요청량과 CPU 사용량이 낮은 상태입니다.

테스트에서는 가상 사용자를 5명, 10명, 20명 순서로 증가시키겠습니다.
최대 20명의 사용자가 동시에 메인 페이지에 접속하는 상태를 30초 동안 유지한 뒤, 사용자를 다시 0명으로 감소시킵니다.

테스트를 다 마췄고요 테스트가 시작되며 초당 요청 수가 증가하고 사용자 증가에 따라 프론트와 백의 cpu 사용량도 함께 증가하는 것을 확인할 수 있습니다. 메모리 사용량도 급격하게 누적되지 않고 안정적인 범위에서 유지된걸 확인할 수 있습니다.

가상 사용자가 감소하면서 초당 요청 수와 cpu 사용량도 다시 낮아지는걸 확인할 수 있스빈다
테스트 결과 총 요청 중 모든 요청이 정상적으로 처리됐으며, 요청 실패율은 0퍼센트입니다.
응답시간도 목표로 설정한 1초 이내 기준을 만족했습니다.

따라서 qket 운영 환경은 이번 최대 20명의 메인 페이지 접속 테스트에서 안정적으로 요청을 처리한 것으로 판단 할 수 있습니다.
